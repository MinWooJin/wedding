# 배포와 데이터 연결 안내 (2026-10-18)

## 1. GitHub Pages 올리기 (사용자가 직접)

저장소는 아직 원격이 없다. Claude는 원격 연결·푸시를 하지 않는다.

```bash
# 1) GitHub에서 빈 저장소를 만든 뒤 (예: wedding), 이 폴더에서
git remote add origin https://github.com/<계정>/wedding.git
git push -u origin main
```

1. GitHub 저장소 → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. 푸시하면 `.github/workflows/pages.yml`이 돌며 필요한 파일만 모아 배포한다(약 1분).
   - 올라가는 것: `index.html`, `common/`, `groom/`, `bride/`, `classic/`, `css/`, `js/`, `data/`, `gallery/`, `assets/`(그림과 manifest만).
   - 올라가지 않는 것: `docs/`, `tests/`, `tools/`, `apps-script/`, 작업 기록 이미지·JSON, README.
3. 주소는 `https://<계정>.github.io/wedding/`. 입구 페이지에서 세 링크로 간다.
   - `…/wedding/common/` 픽셀 정원, `…/wedding/groom/` 신랑측, `…/wedding/bride/` 신부측.
4. 무료 계정은 **저장소가 공개**여야 Pages를 쓸 수 있다. 사이트에는 docs가 올라가지 않지만 저장소 자체는 누구나 볼 수 있다. 저장소를 비공개로 두려면 GitHub Pro가 필요하다.

배포 뒤 채울 값(`data/config.json`):
- `siteUrl`: `https://<계정>.github.io/wedding/` (공유 링크·카카오 공유 이미지의 절대 주소 기준)
- `guestbookApi`: Apps Script 배포 URL (아래 2절)
- `kakaoJsKey`: 카카오 개발자 콘솔 JavaScript 키. **플랫폼 → Web 사이트 도메인에 `https://<계정>.github.io`만 등록**해 다른 사이트에서 키를 못 쓰게 한다.
- 실제 계좌·전화·사진(`gallery/`). 사진을 넣으면 `gallery/manifest.json`에 파일명을 적는다.

## 2. Google 시트 연결의 보안

구조: **시트는 비공개**다. 하객의 브라우저는 시트를 직접 건드리지 못하고, 우리가 쓴 Apps Script 웹 앱(`apps-script/Code.gs`)의 두 기능만 쓴다.

```
하객 브라우저 ──GET (목록)──▶ Apps Script 웹 앱 ──▶ 비공개 시트
             ──POST (글 1건)─▶  (실행 주체: 나)      (내 계정 권한으로만 읽고 씀)
```

- 배포 설정은 **실행 주체 "나", 액세스 "모든 사용자"**다. "모든 사용자"는 *웹 앱 URL을 호출할 수 있다*는 뜻이지 시트를 볼 수 있다는 뜻이 아니다. 시트 공유 설정은 그대로 "나만"으로 둔다.
- 웹 앱이 내려주는 것은 `닉네임·캐릭터 번호·메시지·시각` 네 가지뿐이다. 이메일·전화 같은 개인정보는 애초에 받지도 저장하지도 않는다.
- 웹 앱 URL은 `config.json`에 들어가므로 공개된다. 그래서 **URL을 아는 사람이 글을 마구 쓰는 것**이 유일한 현실적 위험이고, 아래 장치로 막는다.

| 위험 | 지금 코드가 하는 것 | 데이터 단계에서 더 할 것 |
|---|---|---|
| 도배(스팸) | 닉네임당 1분 1건(`CacheService`), 글 100자·닉네임 10자 제한, 동시 쓰기 잠금 | IP 대신 쓸 수 있는 **기기 토큰(guestId)**을 브라우저가 만들어 보내고 토큰당 하루 상한을 둔다. 시트에 `hidden` 열을 두어 내가 체크하면 목록에서 빠지게 한다(지우지 않고 가리기) |
| 봇의 자동 호출 | 요청 형식 검사 | `config.json`의 공개 토큰 한 줄을 요청에 같이 보내고 서버에서 대조한다(완전한 비밀은 아니지만 무차별 봇은 걸러진다). 글 쓰기 폼에 보이지 않는 입력(허니팟)을 두어 채워져 오면 버린다 |
| 시트 수식 주입 | 없음 | `=`, `+`, `-`, `@`로 시작하는 셀 앞에 `'`를 붙여 저장한다(시트에서 수식으로 실행되지 않게) |
| 화면 스크립트 주입 | 모든 출력은 `esc()`로 이스케이프, 캔버스 글씨는 텍스트로만 그림 | 유지 |
| 목록 호출 폭주 | 목록은 최근 100건만 | `doGet` 결과를 30초 캐시(`CacheService`)해 시트 읽기를 줄인다 |
| 키 노출 | 카카오 JS 키는 공개 키(도메인 제한으로 보호) | 카카오 콘솔에서 사이트 도메인 등록 |

- Apps Script 무료 한도(하루 실행 시간·호출 수)는 청첩장 규모에서는 넉넉하다. 혹시 한도를 넘으면 글쓰기만 잠시 실패하고 사이트 자체는 그대로 열린다(목록은 마지막 성공분을 보여 준다).
- 시트 원본은 내 Google 계정이 지키는 셈이므로 **계정 2단계 인증**을 켜 두는 것이 가장 중요한 보안이다.
- 운영 중 특정 글을 숨기려면 시트에서 해당 행의 `hidden` 열에 체크(데이터 단계에서 추가)하거나 행을 지우면 된다. 목록은 호출 때마다 시트를 읽으므로 바로 반영된다.
