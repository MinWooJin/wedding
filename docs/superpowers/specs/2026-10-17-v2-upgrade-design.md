# 픽셀 청첩장 v2 고도화 설계

작성일: 2026-10-17
상태: 화면·동선 개선 구현(9절). API 연결·실사진은 사용자 요청으로 마지막 단계에 보류. 데이터 모델 등 나머지 v2 확장안은 초안.
선행 문서: `2026-10-16-pixel-wedding-invitation-design.md`

## 0. 왜 고도화가 필요한가

v1은 "게임으로서" 완성됐지만 "청첩장으로서" 빈 곳이 있다. 전날 리뷰에서 확인한 핵심 문제는 다섯 가지다.

1. **첫 화면이 청첩장이 아니다.** 카톡 링크를 연 사람이 처음 보는 것이 닉네임 입력 폼이다. 이름·날짜·인사말이 게임 안에 숨어 있다.
2. **게임을 안 하는 사람은 아무것도 못 본다.** → 일반형 청첩장은 사용자가 **별도로 제작**한다(이 프로젝트 범위 밖). 여기서는 커버에서 그 페이지로 연결만 한다.
3. **길을 잃는다.** 입장 후 "탭해서 이동" 안내가 없고, 방 입구 다섯 곳이 첫 화면 밖에 있으며, 표지판에 글자가 없다.
4. **하객 데이터 모델이 닉네임 기준이다.** 같은 닉네임(예: "지원") 두 사람은 한 명으로 합쳐지고, 1분마다 광장 하객 전원이 재생성되어 순간이동한다.
5. **공유 준비가 안 됐다.** `og:image`가 없어 카톡 미리보기가 글자뿐이고, 방명록 API가 비어 있으면 광장이 텅 빈다.

또 하나의 전제 변화가 있다. **예식은 직계가족만 참석한다.** 이 청첩장을 받는 대부분은 식장에 오지 않는다. 그래서 교통·주차는 소수용 정보이고, 방명록과 마음 전하기, 예식 후 소식이 주인공이다.

## 1. 목표와 비목표

**목표**
- 링크를 연 누구나 3초 안에 "누가, 언제, 어디서"를 본다.
- 게임을 하지 않는 사람은 커버에서 별도 일반형 청첩장으로 바로 이동할 수 있다.
- 게임을 하는 사람은 길을 잃지 않고 5개 공간을 다 둘러본다.
- 하객이 남긴 흔적(캐릭터·메시지)이 정확하고 안정적으로 쌓인다.
- 카톡으로 공유했을 때 미리보기가 예쁘게 뜬다.

**비목표**
- 실시간 멀티플레이(다른 하객이 실시간으로 움직이는 것)
- 셀카 → 캐릭터 생성(레퍼런스 기능이지만 서버 GPU·프라이버시 부담이 큼)
- 결제·축의금 송금 연동(계좌 복사·카카오페이 링크로 충분)
- 간편 보기(스크롤형 일반 청첩장) — 사용자가 별도로 제작

## 2. 정보 구조 변경

```
[커버] ─┬─ 입장하기 ──→ [캐릭터 만들기] ──→ [가든 광장(게임)]
        │                                     │  ☰ 메뉴: 공간 바로가기 · 일반 청첩장 · 내 캐릭터 · 공유
        └─ 청첩장만 볼게요 ─→ (외부) 별도 제작 일반형 청첩장 URL
```

- **커버**가 새 첫 화면이다. 게임 캔버스는 그 뒤에서 미리 로딩된다.
- **일반형 청첩장**은 사용자가 별도로 만든다. `config.classicUrl`에 주소를 넣으면 커버 보조 버튼과 ☰ 메뉴에 링크가 생기고, 비어 있으면 버튼을 숨긴다.
- 재방문자(프로필 있음)는 커버를 건너뛰지 않는다. 커버에서 "다시 입장하기" 버튼만 바뀐다.

## 3. 기능 설계

### P0 — 공개 전 필수

**3.1 커버 화면**
- 구성: 픽셀 아치 아래 두 사람 일러스트(광장 첫 장면을 캔버스로 캡처한 정지화), "민우 ♥ 새암", "2027. 1. 9 토 오전 11:30", 장소 한 줄, 인사말 2~3줄(`config.greeting.cover`).
- 버튼: "정원 입장하기"(주), "청첩장만 볼게요"(보조, `config.classicUrl`이 있을 때만 표시, 새 탭이 아닌 같은 탭 이동).
- 양해 문구(`wedding.notice`)는 커버 하단에 작게 한 번 더 노출한다. 식장에 오지 않는다는 사실이 첫 화면에서 전달돼야 한다.

**3.2 일반형 청첩장 연결**
- 별도 제작 페이지로 가는 링크만 둔다(`config.classicUrl`). 방명록 API를 그쪽에서도 쓰고 싶다면 `apps-script`의 GET/POST 규격(5절)을 그대로 쓰면 된다.

**3.3 길안내**
- 첫 입장 시 코치마크 2단계: "화면을 탭하면 걸어가요" → "아래 문으로 들어가 보세요". 한 번 보면 저장(localStorage).
- 맵 위 문 라벨: 각 문 위에 캔버스 텍스트 배지("예식 안내", "갤러리" …)를 상시 표시한다. 표지판 PNG에 글자가 없으므로 라벨이 실제 안내 역할을 한다.
- HUD 메뉴(☰): 공간 5곳 바로가기. 누르면 페이드 후 해당 방 입구로 순간이동한다. 걷기를 원치 않는 사람을 위한 지름길이다.

**3.4 하객 신원 = 기기 ID**
- 첫 입장 시 `guestId`(UUID)를 만들어 localStorage에 저장하고 모든 POST에 포함한다.
- 시트 열: `timestamp | guestId | nickname | characterId | message | hidden`.
- `doGet`은 guestId 기준으로 최신 1건만 내려준다. 같은 닉네임 두 사람이 따로 보인다.
- 기존 닉네임 키 데이터와의 호환: guestId가 빈 행은 `legacy:<nickname>`으로 취급한다.

**3.5 하객 갱신을 증분 방식으로**
- `setGuests`가 매번 전원을 다시 만드는 대신 guestId로 비교해 새 하객만 추가하고, 사라진 하객만 제거한다. 기존 하객은 위치·배회 상태를 유지한다.
- 새로 나타나는 하객은 광장 입구 쪽에서 걸어 들어와 자기 자리로 간다(레퍼런스의 "입장" 느낌).

**3.6 빈 광장 대응**
- 하객 0명일 때 돌길 위에 안내판 하나: "첫 번째 하객이 되어 주세요". 방명록 정원으로 가는 바로가기.
- 신랑·신부가 15~25초마다 인사말을 자동으로 말한다(탭하지 않아도 장면이 살아 있게).

**3.7 공유 미리보기**
- `og.png`(1200×630): 커버 일러스트 + 이름·날짜. 커버 정지화를 만드는 같은 스크립트로 생성한다.
- `og:url`, `og:image`, `og:image:width/height`, `twitter:card` 메타 추가. 카카오 공유 SDK의 `imageUrl`도 이 파일을 가리킨다.

**3.8 로딩**
- 커버를 먼저 그리고, 에셋 58종은 뒤에서 로드한다. "정원 입장하기" 버튼은 로드가 끝날 때까지 진행 표시를 가진다.

### P1 — 공개 후 1~2주 안에

**3.9 방명록 고도화**
- 광장 HUD에 "축하 남기기" 빠른 버튼(우체통까지 걷지 않아도 됨). 작성 후 광장에서 내 캐릭터 머리 위에 메시지 말풍선.
- 방명록 정원에 "모든 메시지 보기" 목록(최신순, 스크롤). 꽃은 최대 40송이만 보이므로 나머지는 목록으로 본다.
- 운영: 시트 `hidden` 열에 TRUE를 넣으면 숨김(행 삭제 대신). 금칙어는 서버에서 `*`로 치환.

**3.10 이름표 겹침**
- 하객이 많으면 이름표가 겹친다. 플레이어 주변 반경 3칸 안 하객과 방금 탭한 하객만 이름표를 진하게, 나머지는 작고 옅게 그린다. 같은 줄에서 겹치면 y를 한 칸씩 띄운다.

**3.11 내 캐릭터 바꾸기**
- HUD 메뉴 → 닉네임·캐릭터 다시 고르기. guestId는 유지하므로 광장의 내 캐릭터가 갱신된다.

**3.12 가족 예식에 맞춘 안내소**
- 안내소 첫 팝업은 일시·장소·양해 문구만. 지도·교통·주차는 "가족분 안내" 오브젝트(게시판)로 분리한다.

### P2 — 여유 있을 때

**3.13 예식 후 모드**: D-Day 이후 커버 문구가 "감사합니다"로 바뀌고, 갤러리에 본식 사진 섹션(`gallery/manifest.json`의 `after` 배열)이 열린다.
**3.14 단체 사진**: 광장의 현재 하객 전원을 한 장 PNG로 저장(레퍼런스 기능). 갤러리 캡처 억제와는 별개.
**3.15 배경음악**: 기본 꺼짐, HUD에서 켜기. 저작권 없는 잔잔한 곡 1개.
**3.16 성능**: 정적 타일·바닥 오브젝트를 씬 진입 시 오프스크린 캔버스 한 장으로 미리 그려 매 프레임 352번의 타일 그리기를 1번으로 줄인다. 에셋 58종을 아틀라스 한두 장으로 합친다.

## 5. 코드 리뷰 결과

독립 리뷰 에이전트가 읽기 전용으로 검토했고, ★ 표시는 Claude가 브라우저·Node에서 직접 재현한 항목이다. XSS는 발견되지 않았다(오버레이는 `esc()`, 캔버스는 `fillText`).

| # | 심각도 | 결함 | 수정 방향 |
|---|---|---|---|
| 1★ | 높음 | 장식 PNG(bush·lantern·platform 등 9종)는 코드 폴백 그림이 없어, 하나만 로드 실패해도 `objectSprite`가 예외를 던지고 게임이 시작되지 않는다(빈 화면) | 폴백을 투명 1칸 자리표시로 반환, 로드 실패 시 해당 오브젝트만 생략 |
| 2★ | 중상 | 경로 탐색이 문 타일을 통과 경로로 써서, 문 옆 잔디를 탭하면 방으로 빨려 들어간다 | 목적지가 아닌 입구 타일은 경로상 막힘으로 처리 |
| 3 | 높음 | `doGet`이 시트 마지막 100행만 읽고 방문 기록도 그 100행을 차지해, 하객이 150명쯤 되면 초기 메시지가 사라진다 | 방문은 별도 시트에 기기 ID당 1행 갱신, 메시지는 전량(또는 넉넉한 한도) 조회 |
| 4 | 높음(악용) | 닉네임만 바꿔 반복 POST하면 방명록을 도배·밀어내기할 수 있고, 신랑·신부 이름으로도 글을 쓸 수 있다 | 전역 분당 한도, 신랑·신부 이름 예약, 시트 `hidden` 열로 숨김 |
| 5 | 중간 | `=`로 시작하는 입력이 시트에서 수식으로 실행되고, `1/9` 같은 문자열이 날짜로 바뀐다 | B·D열 텍스트 서식 + 앞에 `'` 붙여 저장 |
| 6 | 중간 | "보내기" 연타 시 두 번 등록된다 | 전송 중 버튼 비활성, 서버 쿨다운 확인을 락 안으로 |
| 7 | 중간(추정) | 캔버스·사진 뷰어에 `touch-action: none`이 없어 실제 폰에서 드래그 스크롤·사진 스와이프가 중간에 끊길 수 있다 | 두 요소에 `touch-action: none` |
| 8★ | 중하 | 1분마다 하객 전원이 재생성되어 순간이동한다(같은 데이터로 갱신해도 8명 중 7명 점프) | 3.5 증분 갱신 |
| 9 | 중간 | 같은 닉네임 두 사람이 한 명으로 합쳐지고 서로의 글을 막는다 | 3.4 기기 ID |
| 10 | 중하 | 방문 등록이 끝나야 하객 목록을 불러오고 POST에 타임아웃이 없어, Apps Script가 느리면 1분간 광장이 빈다 | 병렬 호출 + 타임아웃 |
| 11 | 중간(추정) | 예식 당일 동시 접속이 몰리면 Apps Script 동시 실행 한도에 걸릴 수 있다 | `doGet` 결과를 CacheService에 30~60초 캐시, POST 때 무효화 |
| 12 | 중하(추정) | iOS 15.0~15.3에서 `structuredClone` 미지원으로 빈 화면 가능 | JSON 복제로 대체, 부팅을 async 함수로 감싸기 |
| 13 | 낮음 | 안내소 첫 입장 시 페이드 중에 팝업이 떠서 팝업 뒤 방이 검게 보인다 | 페이드 완료 후 팝업 |

| 15 | 중하(추정) | 갤러리가 원본 사진을 한꺼번에 받아 썸네일을 만든다. 저사양 폰 인앱 브라우저에서 메모리 부족 가능 | 썸네일 파일을 따로 두고 원본은 뷰어에서만 로드 |
| 16 | 낮음 | 화면 위쪽 하객의 말풍선이 HUD에 가리거나 화면 밖으로 나간다 | 말풍선 y를 화면 안으로 클램프 |

**테스트 공백**: 에셋 일부 로드 실패, 경로가 입구를 지나는 경우, Apps Script 로직(테스트 0개), 입력(탭·드래그·pointercancel)과 뷰어 스와이프, 오버레이 중복 제출·페이드 중 열림.

**Apps Script 재설계(3.4와 합침)**
- 시트 2개: `messages`(timestamp, guestId, nickname, characterId, message, hidden), `visitors`(guestId, nickname, characterId, firstSeen, lastSeen) — 방문은 guestId당 1행을 갱신한다.
- `doGet`: 숨김 제외 메시지 전량 + 방문자 전량을 하나의 JSON으로, CacheService 45초 캐시.
- `doPost`: 전역 분당 20건 한도, guestId당 쿨다운, 신랑·신부 이름 사용 거부, 텍스트 서식 저장, 락 안에서 검사와 기록.
- Apps Script 로직을 순수 함수로 분리해 Node에서 테스트한다(`apps-script/logic.js`를 `Code.gs`에 포함하는 빌드 한 줄).

## 6. 작업 순서 제안

1. 버그 수정과 데이터 모델(3.4, 3.5, 5절 #1~#13) — 공개 후에 바꾸면 시트 데이터 이전이 필요하므로 가장 먼저.
2. 커버·공유 미리보기·로딩(3.1, 3.2, 3.7, 3.8).
3. 길안내·빈 광장(3.3, 3.6).
4. 여기까지 끝나면 실제 데이터 입력 → 공개.
5. P1 → P2.

## 7. 코덱스에 맡길 그림

- 커버 일러스트는 광장 첫 장면 캡처로 해결하므로 새 그림이 필요 없다.
- 문 라벨은 캔버스 텍스트로 처리하므로 표지판 재작화가 필요 없다.

### 8.3 공간별 화면 방향

- **광장**: 아치·두 사람은 유지. 비어 있는 긴 중앙 길 일부를 줄이고 시작 위치에서 방명록/갤러리 방향을 알 수 있게 배치한다.
  `welcome-board`, `chair`, `petal-pile` 등 이미 등록된 미사용 소품을 먼저 시험 배치한다. 하객이 설 영역과 통과할 길을 분리한다.
- **방명록 정원**: 주인공은 우체통과 메시지다. 우체통 앞까지 이어지는 길, 편지 쓰기 받침대, 빈 화단의 첫 축하 안내를 둔다.
  고정 ‘축하 남기기’와 ‘모든 메시지’ 버튼을 제공하고, 꽃 선택 시 작성자/본문 카드로 이어진다.
- **갤러리**: 실제 사진 입력이 먼저다. 현재 사진 표시 영역 30×28px은 인물 식별이 어려우므로 더 넓은 액자와 DOM 썸네일 목록을 검토한다.
  사진 0장이면 빈 복도 대신 준비 안내와 다른 공간으로 가는 버튼을 제공. 사진을 AI로 신랑·신부 실사진처럼 대신 만들지 않는다.
- **이야기 길**: 같은 표지판 반복 대신 만남/프러포즈/결혼의 세 장면을 소품·짧은 제목으로 구분. 실제 화면에서 오른쪽 표지판이 나무에 가려져 장식과 클릭 대상의 겹침도 조정해야 한다. 벤치의 두 사람은 현재 서 있는 PNG를 가려 앉힌 방식이므로, 필요할 때 앉은 포즈를 별도 제작한다.
- **안내소**: 데스크를 중심으로 일시·연락·가족분 안내를 묶고 이름표를 붙인다. 자동 팝업은 페이드가 끝난 뒤 열어 방이 검게 가려지는 현상을 없앤다.
- **마음 전하기**: 상자 두 개보다 양측 봉투함/테이블이 맥락에 맞는다. 공유는 별도 편지 받침대와 명확한 버튼으로 구분한다.

우선 기존 타일과 소품으로 재배치하고, 필요하면 안내소 벽/갤러리 벽/정원 가장자리처럼 독립적인 배경 띠나 모듈만 추가한다.
배경에 버튼·텍스트·하객을 합성하지 않으며, 모바일 세로 화면의 HUD/하단 버튼 영역은 비워 둔다.

제작 공통 기준: 기존 자연 정원과 크림/연분홍 팔레트, 동일 시점·픽셀 밀도·광원, 오브젝트 투명 배경/아래 정렬.
실제 보이는 알파 bbox도 확인하고, 오브젝트 전체 크기와 바닥 충돌 폭을 구분한다. 1배 모바일에서 기능을 알아볼 수 있는지 먼저 검증한다.

### 8.5 v2 코드 리뷰에 추가할 항목

아래는 소스에서 확인한 결함/검증 공백이며, 기존 5절의 중복 제출·닉네임 신원·부분 로드 실패 등과 함께 수정한다.

1. **성공한 빈 목록을 반영하지 않음** — `main.js`의 `if (list.length)` 때문에 서버에서 글이 모두 삭제돼도 이전 꽃과 하객이 계속 남는다.
   `api.js`가 오류와 정상 빈 목록을 모두 `[]`로 반환하므로 성공/실패를 구분한 뒤 정상 빈 배열도 적용해야 한다.
2. **갤러리 썸네일의 깊이 순서** — `GalleryScene.draw()`는 전체 씬(캐릭터·말풍선 포함)을 그린 뒤 썸네일을 올린다.
   사진 위에 캐릭터/말풍선이 겹치는 경우 사진이 마지막에 덮을 수 있다. 액자와 썸네일을 하나의 드로어블로 합쳐 y정렬에 참여시킨다.
3. **도착과 막힘을 같은 상태로 취급** — `stepToward()`의 `arrived = !moved || remaining < 0.5`와 `walkTo()`의 경로 실패 직선 폴백 조합.
   막힌 이동에서도 도착 콜백을 호출할 수 있다. 이동 실패와 실제 도착을 분리하고, 상호작용 직전에 거리/대상을 다시 확인한다.
4. **그림과 탭 우선순위 불일치** — 렌더는 y정렬이지만 NPC 선택은 배열의 첫 항목, 오브젝트 선택은 배열 역순이다.
   겹친 하객/소품에서 화면에 보이는 대상이 선택되도록 최종 그리기 순서를 재사용한다. 투명 여백이 넓은 소품은 히트 영역도 조정한다.
5. **접근성/모바일 입력** — 캔버스 안 목적지·메시지는 DOM에서 읽거나 키보드로 선택할 수 없다. 팝업은 dialog 속성·초점 이동/복귀·Escape 처리가 없고, 입력은 placeholder만 있다.
   DOM 메뉴/메시지 목록/라벨을 제공하고 일반형 링크만으로 대체하지 않는다. viewport의 확대 금지도 재검토한다.
6. **큰 글씨·키보드·짧은 화면** — 첫 인트로의 자동 포커스는 실기기에서 키보드를 즉시 열 수 있다.
   작성 팝업의 보내기/닫기가 키보드 뒤로 숨지 않는지, safe area와 가변 화면 높이를 포함해 실기기에서 확인한다.

## 9. 화면·동선 개선 구현 기록 (2026-10-17)

사용자 승인: ‘방명록 API와 갤러리 사진은 마지막에 한 번에 추가, 나머지는 진행’.

### 적용 사항

- **커버**: 기존 아치·신랑·신부 PNG로 구성한 정원 장면, 이름·예식일·장소·가족 예식 안내를 먼저 표시한다.
  에셋 로딩 중 진행 문구를 표시하고 완료되면 입장 버튼을 활성화한다. 재방문자도 커버를 거친다.
  `classicUrl`이 설정되어 있을 때만 일반형 청첩장 링크를 표시한다. 일반형 페이지 자체는 구현하지 않았다.
- **공통 화면**: 현재 공간명·한 줄 설명·빈 상태/메시지 수·내 위치 복귀와 하단 광장/축하 작성/전체 메시지 버튼.
  6개 공간 바로가기, 사용 안내, 내 캐릭터/닉네임 변경, 소식 공유 메뉴를 제공한다.
  카메라는 실제 헤더와 하단 안내 카드의 크기를 측정해 캐릭터를 보이는 영역에 맞춘다.
- **광장**: 32행에서 26행(352×832)으로 단축. 첫 입구 21→15행, 방명록 25→19행.
  모든 표지판에 상시 이름을 붙였고, 표지판과 라벨을 눌러 해당 공간으로 이동할 수 있다.
  기존 preset-4를 ‘정원 안내인’으로 재사용했다. 실하객으로 집계하지 않는다.
- **길·배치**: 기존 G/N 타일을 캔버스 클리핑해 바깥 모서리를 둥글게 연결한다. 별도 타일 생성 없음.
  목적지 표시와 플레이어 발밑 표시, 48×72 캐릭터 크기를 고려한 하객 간격, 가까운/말하는 하객 이름표 강조.
  반복 데이터 갱신 시 기존 NPC 객체·위치·배회 상태를 보존하며 신규 하객만 배치한다.
- **방명록**: 어느 공간에서나 작성 가능. 글자 수, 입력 검증, 전송 중 중복 클릭/닫기 방지, 실패 시 본문 유지,
  취소 후 재진입 시 초안 복원, 완료 피드백, 전체 메시지 목록과 빈 상태를 추가했다.
  API가 비어 있으면 **기기 저장 미리보기**라고 명시하고 localStorage 전용 키에 최대 100건 저장한다.
  다른 기기/서버로 전송하지 않으며 실제 방명록 연결 시 자동 업로드하지 않는다. 개별 미리보기 삭제도 제공한다.
- **공간별 보완**: 방명록 우체통 교체/접근 길 연결, 갤러리 준비 안내와 96px 액자/45×42 썸네일,
  액자 콘텐츠를 캐릭터와 함께 깊이 정렬. 이야기 길의 나무가 가리던 팻말을 재배치하고 제목을 상시 표시했다.
  이야기 전체 보기와 양측 계좌/공유의 DOM 바로가기를 제공한다. 안내소 오브젝트 이름도 상시 표시한다.
  공유 비석은 편지 소품으로 바꾸었다. 가족 예식과 충돌하던 ‘오늘 꼭 뵈어요’ 문구를 교체했다.
  안내소와 마음 전하기 방은 12행(352×384), 빈 갤러리는 최소 11행(352×352)으로 넓히고 기존 화분을 재배치했다.
- **입력·안정성**: 모달 dialog 속성, 초점 이동/복귀/Tab 순환/Escape, 입력 라벨, 화면 확대 허용,

  막힘/도착 상태를 분리하고 경로 실패 시 상호작용 콜백을 실행하지 않는다. 목적지가 아닌 문을 경유하지 않는다.

### 정적 바닥 캐시

- `Renderer.drawGround()`에서 타일·길 모서리·바닥 장식을 오프스크린 캔버스에 한 번 합성한다.
  광장 297칸의 타일과 이웃 정보를 매 프레임 다시 계산하지 않고, 이후에는 바닥 이미지 한 번과 동적 요소만 그린다.
- 캐릭터 모션·꽃·라벨·말풍선·깊이 정렬은 동적으로 유지한다. 카메라 이동/리사이즈는 기존 바닥 캐시를 재사용한다.
- 타일 세트·배경·바닥 오브젝트 목록 교체 시 재합성한다. 맵 내용을 직접 편집하는 도구에서는 `invalidateGround(map)`으로 무효화할 수 있다.
- 200만 픽셀을 넘는 긴 맵이나 캐시 캔버스를 만들 수 없는 환경은 기존 렌더링으로 돌아간다.
  정적 작업 횟수 감소를 검증했으며 실제 저사양 기기의 FPS 향상 수치를 측정한 것은 아니다.
