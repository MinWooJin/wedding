# 픽셀 청첩장 v2 고도화 설계

작성일: 2026-10-17
상태: 초안(사용자 검토 대기) — 제품 리뷰(Claude, 브라우저 실사용) + 코드 리뷰(독립 에이전트) 반영
선행 문서: `2026-10-16-pixel-wedding-invitation-design.md`

## 0. 왜 고도화가 필요한가

v1은 "게임으로서" 완성됐지만 "청첩장으로서" 빈 곳이 있다. 전날 리뷰에서 확인한 핵심 문제는 다섯 가지다.

1. **첫 화면이 청첩장이 아니다.** 카톡 링크를 연 사람이 처음 보는 것이 닉네임 입력 폼이다. 이름·날짜·인사말이 게임 안에 숨어 있다.
2. **게임을 안 하는 사람은 아무것도 못 본다.** → 일반형 청첩장은 사용자가 **별도로 제작**한다(이 프로젝트 범위 밖). 여기서는 커버에서 그 페이지로 연결만 한다.
3. **길을 잃는다.** 입장 후 "탭해서 이동" 안내가 없고, 방 입구 다섯 곳이 첫 화면 밖에 있으며, 표지판에 글자가 없다.
4. **하객 데이터 모델이 닉네임 기준이다.** 같은 닉네임(예: "지원") 두 사람은 한 명으로 합쳐지고, 1분마다 광장 하객 전원이 재생성되어 순간이동한다.
5. **공유 준비가 안 됐다.** `og:image`가 없어 카톡 미리보기가 글자뿐이고, 방명록 API가 비어 있으면 광장이 텅 빈다.

또 하나의 전제 변화가 있다. **예식은 직계가족만 참석한다.** 이 청첩장을 받는 대부분은 식장에 오지 않는다. 그래서 교통·주차는 소수용 정보이고, 방명록과 마음 전하기, 예식 후 소식이 주인공이다.

## 1. 목표와 비목표

**목표**
- 링크를 연 누구나 3초 안에 "누가, 언제, 어디서"를 본다.
- 게임을 하지 않는 사람은 커버에서 별도 일반형 청첩장으로 바로 이동할 수 있다.
- 게임을 하는 사람은 길을 잃지 않고 5개 공간을 다 둘러본다.
- 하객이 남긴 흔적(캐릭터·메시지)이 정확하고 안정적으로 쌓인다.
- 카톡으로 공유했을 때 미리보기가 예쁘게 뜬다.

**비목표**
- 실시간 멀티플레이(다른 하객이 실시간으로 움직이는 것)
- 셀카 → 캐릭터 생성(레퍼런스 기능이지만 서버 GPU·프라이버시 부담이 큼)
- 결제·축의금 송금 연동(계좌 복사·카카오페이 링크로 충분)
- 간편 보기(스크롤형 일반 청첩장) — 사용자가 별도로 제작

## 2. 정보 구조 변경

```
[커버] ─┬─ 입장하기 ──→ [캐릭터 만들기] ──→ [가든 광장(게임)]
        │                                     │  ☰ 메뉴: 공간 바로가기 · 일반 청첩장 · 내 캐릭터 · 공유
        └─ 청첩장만 볼게요 ─→ (외부) 별도 제작 일반형 청첩장 URL
```

- **커버**가 새 첫 화면이다. 게임 캔버스는 그 뒤에서 미리 로딩된다.
- **일반형 청첩장**은 사용자가 별도로 만든다. `config.classicUrl`에 주소를 넣으면 커버 보조 버튼과 ☰ 메뉴에 링크가 생기고, 비어 있으면 버튼을 숨긴다.
- 재방문자(프로필 있음)는 커버를 건너뛰지 않는다. 커버에서 "다시 입장하기" 버튼만 바뀐다.

## 3. 기능 설계

### P0 — 공개 전 필수

**3.1 커버 화면**
- 구성: 픽셀 아치 아래 두 사람 일러스트(광장 첫 장면을 캔버스로 캡처한 정지화), "민우 ♥ 새암", "2027. 1. 9 토 오전 11:30", 장소 한 줄, 인사말 2~3줄(`config.greeting.cover`).
- 버튼: "정원 입장하기"(주), "청첩장만 볼게요"(보조, `config.classicUrl`이 있을 때만 표시, 새 탭이 아닌 같은 탭 이동).
- 양해 문구(`wedding.notice`)는 커버 하단에 작게 한 번 더 노출한다. 식장에 오지 않는다는 사실이 첫 화면에서 전달돼야 한다.

**3.2 일반형 청첩장 연결**
- 별도 제작 페이지로 가는 링크만 둔다(`config.classicUrl`). 방명록 API를 그쪽에서도 쓰고 싶다면 `apps-script`의 GET/POST 규격(5절)을 그대로 쓰면 된다.

**3.3 길안내**
- 첫 입장 시 코치마크 2단계: "화면을 탭하면 걸어가요" → "아래 문으로 들어가 보세요". 한 번 보면 저장(localStorage).
- 맵 위 문 라벨: 각 문 위에 캔버스 텍스트 배지("예식 안내", "갤러리" …)를 상시 표시한다. 표지판 PNG에 글자가 없으므로 라벨이 실제 안내 역할을 한다.
- HUD 메뉴(☰): 공간 5곳 바로가기. 누르면 페이드 후 해당 방 입구로 순간이동한다. 걷기를 원치 않는 사람을 위한 지름길이다.

**3.4 하객 신원 = 기기 ID**
- 첫 입장 시 `guestId`(UUID)를 만들어 localStorage에 저장하고 모든 POST에 포함한다.
- 시트 열: `timestamp | guestId | nickname | characterId | message | hidden`.
- `doGet`은 guestId 기준으로 최신 1건만 내려준다. 같은 닉네임 두 사람이 따로 보인다.
- 기존 닉네임 키 데이터와의 호환: guestId가 빈 행은 `legacy:<nickname>`으로 취급한다.

**3.5 하객 갱신을 증분 방식으로**
- `setGuests`가 매번 전원을 다시 만드는 대신 guestId로 비교해 새 하객만 추가하고, 사라진 하객만 제거한다. 기존 하객은 위치·배회 상태를 유지한다.
- 새로 나타나는 하객은 광장 입구 쪽에서 걸어 들어와 자기 자리로 간다(레퍼런스의 "입장" 느낌).

**3.6 빈 광장 대응**
- 하객 0명일 때 돌길 위에 안내판 하나: "첫 번째 하객이 되어 주세요". 방명록 정원으로 가는 바로가기.
- 신랑·신부가 15~25초마다 인사말을 자동으로 말한다(탭하지 않아도 장면이 살아 있게).

**3.7 공유 미리보기**
- `og.png`(1200×630): 커버 일러스트 + 이름·날짜. 커버 정지화를 만드는 같은 스크립트로 생성한다.
- `og:url`, `og:image`, `og:image:width/height`, `twitter:card` 메타 추가. 카카오 공유 SDK의 `imageUrl`도 이 파일을 가리킨다.

**3.8 로딩**
- 커버를 먼저 그리고, 에셋 58종은 뒤에서 로드한다. "정원 입장하기" 버튼은 로드가 끝날 때까지 진행 표시를 가진다.

### P1 — 공개 후 1~2주 안에

**3.9 방명록 고도화**
- 광장 HUD에 "축하 남기기" 빠른 버튼(우체통까지 걷지 않아도 됨). 작성 후 광장에서 내 캐릭터 머리 위에 메시지 말풍선.
- 방명록 정원에 "모든 메시지 보기" 목록(최신순, 스크롤). 꽃은 최대 40송이만 보이므로 나머지는 목록으로 본다.
- 운영: 시트 `hidden` 열에 TRUE를 넣으면 숨김(행 삭제 대신). 금칙어는 서버에서 `*`로 치환.

**3.10 이름표 겹침**
- 하객이 많으면 이름표가 겹친다. 플레이어 주변 반경 3칸 안 하객과 방금 탭한 하객만 이름표를 진하게, 나머지는 작고 옅게 그린다. 같은 줄에서 겹치면 y를 한 칸씩 띄운다.

**3.11 내 캐릭터 바꾸기**
- HUD 메뉴 → 닉네임·캐릭터 다시 고르기. guestId는 유지하므로 광장의 내 캐릭터가 갱신된다.

**3.12 가족 예식에 맞춘 안내소**
- 안내소 첫 팝업은 일시·장소·양해 문구만. 지도·교통·주차는 "가족분 안내" 오브젝트(게시판)로 분리한다.

### P2 — 여유 있을 때

**3.13 예식 후 모드**: D-Day 이후 커버 문구가 "감사합니다"로 바뀌고, 갤러리에 본식 사진 섹션(`gallery/manifest.json`의 `after` 배열)이 열린다.
**3.14 단체 사진**: 광장의 현재 하객 전원을 한 장 PNG로 저장(레퍼런스 기능). 갤러리 캡처 억제와는 별개.
**3.15 배경음악**: 기본 꺼짐, HUD에서 켜기. 저작권 없는 잔잔한 곡 1개.
**3.16 성능**: 정적 타일·바닥 오브젝트를 씬 진입 시 오프스크린 캔버스 한 장으로 미리 그려 매 프레임 352번의 타일 그리기를 1번으로 줄인다. 에셋 58종을 아틀라스 한두 장으로 합친다.

## 5. 코드 리뷰 결과

독립 리뷰 에이전트가 읽기 전용으로 검토했고, ★ 표시는 Claude가 브라우저·Node에서 직접 재현한 항목이다. XSS는 발견되지 않았다(오버레이는 `esc()`, 캔버스는 `fillText`).

| 10 | 중하 | 방문 등록이 끝나야 하객 목록을 불러오고 POST에 타임아웃이 없어, Apps Script가 느리면 1분간 광장이 빈다 | 병렬 호출 + 타임아웃 |

| 16 | 낮음 | 화면 위쪽 하객의 말풍선이 HUD에 가리거나 화면 밖으로 나간다 | 말풍선 y를 화면 안으로 클램프 |

**테스트 공백**: 에셋 일부 로드 실패, 경로가 입구를 지나는 경우, Apps Script 로직(테스트 0개), 입력(탭·드래그·pointercancel)과 뷰어 스와이프, 오버레이 중복 제출·페이드 중 열림.

**Apps Script 재설계(3.4와 합침)**
- 시트 2개: `messages`(timestamp, guestId, nickname, characterId, message, hidden), `visitors`(guestId, nickname, characterId, firstSeen, lastSeen) — 방문은 guestId당 1행을 갱신한다.
- `doGet`: 숨김 제외 메시지 전량 + 방문자 전량을 하나의 JSON으로, CacheService 45초 캐시.
- `doPost`: 전역 분당 20건 한도, guestId당 쿨다운, 신랑·신부 이름 사용 거부, 텍스트 서식 저장, 락 안에서 검사와 기록.
- Apps Script 로직을 순수 함수로 분리해 Node에서 테스트한다(`apps-script/logic.js`를 `Code.gs`에 포함하는 빌드 한 줄).

## 6. 작업 순서 제안

1. 버그 수정과 데이터 모델(3.4, 3.5, 5절 #1~#13) — 공개 후에 바꾸면 시트 데이터 이전이 필요하므로 가장 먼저.
2. 커버·공유 미리보기·로딩(3.1, 3.2, 3.7, 3.8).
3. 길안내·빈 광장(3.3, 3.6).
4. 여기까지 끝나면 실제 데이터 입력 → 공개.
5. P1 → P2.

## 7. 코덱스에 맡길 그림

- 커버 일러스트는 광장 첫 장면 캡처로 해결하므로 새 그림이 필요 없다.
- 문 라벨은 캔버스 텍스트로 처리하므로 표지판 재작화가 필요 없다.
- 필요한 것은 **방 입구 아이콘 5종**(32×32: 편지·액자·하트 길·우체통·선물상자) 정도이며, 메뉴 항목에 함께 쓴다. 선택 사항이다.
