# 픽셀 게스트북 스타일 모바일 청첩장 — 설계 문서

작성일: 2026-10-16
상태: 승인됨

## 1. 목표

하객이 모바일 브라우저(카카오톡 인앱 포함)로 접속해 닉네임을 입력하고 픽셀 캐릭터를 고른 뒤,
터치로 이동하며 가든 웨딩 맵을 탐험하는 청첩장. 정보 전달(일시·장소·연락처·계좌)과
사진 갤러리, 방명록을 게임 공간 안에 배치한다.

레퍼런스: Instagram @dding_one 픽셀 게스트북 릴. 가져올 요소는 **비주얼 톤**이다.
- 야외 가든: 꽃 아치, 울타리, 나무, 가운데 잔디길이 아래로 이어지는 세로형 구도
- 4등신 "픽셀 치비" 캐릭터, 진한 외곽선, 머리 위 닉네임 태그
- 캐릭터 옆 말풍선으로 메시지 표시

레퍼런스와 다른 점: 사진 기반 AI 캐릭터 생성 없음. 프리셋 캐릭터 선택 + 여러 방 탐험.

## 2. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 호스팅 | GitHub Pages (정적) | 사용자 요구 |
| 데이터 저장 | Google 스프레드시트 + Apps Script 웹앱 | 신랑신부가 시트에서 직접 확인·삭제 가능 |
| 맵 구조 | 허브(가든 광장) + 개별 방 5개, 입구 터치 시 화면 전환 | 각 방이 한 화면이라 제작·탐색이 쉽고 정보가 주제별로 묶임 |
| 에셋 | 코드 내 픽셀 배열로 직접 정의 | 외부 파일 의존 없음, 바로 완성 |
| 캡처 방지 | 기본 억제 (OS 스크린샷은 못 막음을 명시) | 웹의 기술적 한계 |
| 기술 스택 | 바닐라 JS + Canvas, 팝업은 DOM 오버레이, 빌드 도구 없음 | 의존성 0, 로딩 빠름, 인앱 브라우저 안전 |

## 3. 사용자 플로우

```
[인트로] → [닉네임 입력 + 캐릭터 선택] → [허브: 가든 광장]
                                         ├─ 예식 안내소
                                         ├─ 갤러리관
                                         ├─ 우리 이야기 길
                                         ├─ 방명록 정원
                                         └─ 마음 전하는 곳
```

- 닉네임(2~10자)과 캐릭터 ID는 localStorage에 저장. 재접속 시 입력 화면을 건너뛰고 광장에서 시작.
- 모든 방에서 하단 좌측 "광장으로" 버튼 또는 방 입구 타일로 허브 복귀.

## 4. 맵별 설계

### 4.1 허브: 가든 광장
- 상단 중앙 꽃 아치 + 신랑·신부 NPC. 인접 타일에서 터치하면 인사말 말풍선(설정 파일의 문구 배열에서 랜덤).
- 좌우 울타리·나무·꽃밭, 중앙 잔디길. 하단부에 5개 입구(표지판 + 돌길/문 타일).
- 방명록을 남긴 하객 캐릭터(최근 30명)가 광장에 서 있음. 터치 시 그 사람 메시지 말풍선.
- 상단 고정 HUD: `신랑 ♥ 신부 | 날짜 | D-N` (픽셀 폰트). D-day 지나면 "감사합니다".

### 4.2 예식 안내소 (실내)
- 입장 시 안내판 팝업 1회: 날짜·시간·장소·홀.
- 오브젝트: `지도 액자`(카카오맵/네이버지도/티맵 딥링크 버튼), `전화기`(신랑·신부·양가 혼주 전화/문자 링크), `달력`(.ics 다운로드).
- 교통 게시판: 지하철·버스·주차 안내 텍스트(설정 파일).

### 4.3 갤러리관
- 가로로 긴 복도. 양쪽 벽에 액자(썸네일 48×48px 상당), 바닥은 나무 마루.
- 액자 앞 타일에 서면 액자 하이라이트. 터치 시 DOM 오버레이 뷰어로 확대, 좌우 스와이프로 이동.
- `gallery/manifest.json`의 파일명 목록만큼 액자가 자동 생성. 복도 길이도 사진 수에 맞춰 늘어남.
- 캡처 억제:
  - 뷰어는 `<img>` 대신 canvas에 그려 길게 누르기 저장·드래그 차단
  - `contextmenu` 차단, `user-select: none`, `-webkit-touch-callout: none`
  - `visibilitychange`로 탭이 숨겨지면 뷰어 자동 닫힘
  - 한계: OS 스크린샷·화면 녹화는 막을 수 없음

### 4.4 우리 이야기 길 (야외)
- 가로로 긴 산책로. 이정표가 순서대로 배치되고 다가가면 연도·한 문장·작은 픽셀 아이콘(커피잔, 반지 등) 표시.
- 타임라인 항목은 설정 파일 배열. 끝에 벤치에 앉은 두 캐릭터 장면.

### 4.5 방명록 정원
- 꽃밭 사이 우체통. 터치 → 입력 폼(닉네임 자동, 본문 최대 100자). 비밀번호 없음.
- 제출 → Apps Script `doPost` → 시트에 `timestamp, nickname, characterId, message` 저장.
- 성공 시 내 캐릭터 머리 위 하트 이펙트, 정원에 꽃 한 송이 추가.
- 기존 메시지는 꽃으로 표시, 터치 시 말풍선. 신랑신부는 시트에서 행 삭제로 관리.
- 전송 중복 방지: 같은 닉네임 1분 1회(클라이언트 + 서버 양쪽).

### 4.6 마음 전하는 곳 (정자)
- 신랑측·신부측 보관함 2개. 터치 → 은행·계좌번호·예금주, "복사" 버튼, 카카오페이 링크(선택, 설정에 있을 때만).
- 공유 비석: 링크 복사, 카카오톡 공유(Kakao JS SDK 키가 설정에 있을 때만 활성, 없으면 링크 복사만).

## 5. 캐릭터 & 조작

- 프리셋 10종: 헤어 5종 × 피부톤 2종, 옷 색은 캐릭터별 고정 팔레트. 내부 16×24px(화면 3배율 시 72px) 4등신.
- 애니메이션: 4방향, 걷기 2프레임(idle 1프레임).
- 선택 화면: 좌우 화살표로 넘기며 큰 미리보기, 걷기 애니 재생.
- 이동: 터치 지점으로 직선 이동. 벽/오브젝트 충돌 시 그 자리에서 멈춤. 경로 탐색 없음.
- 입구 타일을 밟으면 0.3초 페이드 아웃/인으로 방 전환.
- 닉네임 태그는 머리 위 상시 표시. 말풍선은 3초 후 사라짐.
- 다른 하객 캐릭터는 정지 상태(이동 없음), 가끔 방향만 바꿈.

## 6. 렌더링 & 레이아웃

- 내부 해상도 기준 가로 176px(타일 16px × 11), 세로는 뷰포트 비율에 맞춤. 정수 배율(2~4배)로 확대, `image-rendering: pixelated`.
- 모바일: 전체 화면. PC: 가운데 폰 비율(9:19.5) 프레임, 양옆 배경색.
- 텍스트: 닉네임 태그·말풍선은 canvas `fillText`(8px 시스템 폰트)를 내부 해상도에서 그린 뒤 정수 배율로 확대해 픽셀 느낌을 냄. HUD·팝업은 DOM 레이어(웹폰트 Galmuri 또는 시스템 폰트). 별도 비트맵 폰트는 만들지 않음(YAGNI).

## 8. 데이터

### config.json (주요 키)
```json
{
  "groom": {"name": "", "phone": "", "parents": [{"role": "아버지", "name": "", "phone": ""}], "account": {"bank": "", "number": "", "holder": "", "kakaopay": ""}},
  "bride": { "...동일 구조..." },
  "wedding": {"date": "2027-00-00T00:00:00+09:00", "venue": "", "hall": "", "address": "", "map": {"kakao": "", "naver": "", "tmap": ""}, "transport": {"subway": "", "bus": "", "parking": ""}},
  "greetings": ["와주셔서 감사해요", "..."],
  "timeline": [{"year": "2019", "text": "", "icon": "coffee"}],
  "guestbookApi": "https://script.google.com/macros/s/.../exec",
  "kakaoJsKey": ""
}
```

### Apps Script
- `doGet()` → 최근 100건 JSON `[{t, n, c, m}]`, CORS 허용.
- `doPost(e)` → 검증(닉네임 2~10자, 메시지 1~100자, characterId 0~9), 같은 닉네임 60초 내 재요청 거부, 시트 append.
- 클라이언트는 `fetch` with `Content-Type: text/plain`으로 POST(프리플라이트 회피).

## 9. 에러 처리

- API GET 실패: 광장 하객 캐릭터와 방명록 꽃 생략, 나머지 기능 정상. 콘솔 경고만.
- API POST 실패: "잠시 후 다시 시도해주세요" 토스트, 입력 내용 유지.
- 사진 로드 실패: 해당 액자에 "준비 중" 플레이스홀더.
- config.json 누락 키: 해당 오브젝트/버튼 비표시(예: 카카오페이 링크 없으면 버튼 없음).
- localStorage 사용 불가(시크릿 모드 등): 매번 입력 화면부터 시작, 오류 없이 진행.

## 10. 테스트

- Node 단위 테스트(`node --test`): 타일 충돌 판정, 입구 트리거, 스프라이트 팔레트 조합 10종 생성, 이동 스텝, D-day 계산, config 기본값 병합, 방명록 입력 검증, 갤러리 액자 배치.
- 수동 검증(내장 브라우저 375×812): 인트로 → 광장 → 5개 방 진입·복귀, 방명록 제출(테스트 시트), 갤러리 확대·스와이프·탭 전환 시 닫힘, PC 폭에서 폰 프레임 표시.
