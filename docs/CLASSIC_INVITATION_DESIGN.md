# 일반형 모바일 청첩장 설계 + 코덱스 작업 지시 (2026-10-18, Claude)

픽셀 게스트북(현재 앱)과 별개로, 부모님 세대 하객도 바로 읽을 수 있는 **일반형 모바일 청첩장**을 같은 저장소에서 제공한다.
신랑측·신부측 두 주소로 나누되 **디자인·내용은 완전히 같고 계좌 안내만 다르다.**

## 1. 주소 구조 (최종 목표)

| 경로 | 내용 | 비고 |
|---|---|---|
| `/` | `/common/`으로 즉시 이동하는 1줄짜리 안내 페이지 | 검색 노출 막음(`noindex`) |
| `/common/` | 픽셀 게스트북(현재 앱) | **이번 작업에서는 건드리지 않는다.** 이동은 Claude가 나중에 한다 |
| `/groom/` | 일반형 청첩장, 마음 전하는 곳에 **신랑측 계좌만** | 신랑이 지인에게 보내는 링크 |
| `/bride/` | 일반형 청첩장, 마음 전하는 곳에 **신부측 계좌만** | 신부가 지인에게 보내는 링크 |
| `/classic/` | 두 페이지가 함께 쓰는 CSS·JS·그림 | 페이지마다 복사하지 않는다 |
| `/data/config.json` | 세 페이지가 공유하는 설정(이름·일시·장소·계좌·문구) | 이미 있음. 새 필드만 추가 |
| `/gallery/` | 세 페이지가 공유하는 사진과 `manifest.json` | 이미 있음(비어 있음) |

- 전부 정적 파일, 빌드 없음, GitHub Pages 하위 경로(`/저장소명/…`)에서도 동작해야 하므로 **모든 참조는 상대 경로**(`../classic/app.css`, `../data/config.json`).
- 단계: ① 코덱스가 `/groom/`, `/bride/`, `/classic/`을 만든다(이 문서). ② Claude가 픽셀 앱을 `/common/`으로 옮기고 루트 이동 페이지를 만든다. ③ 데이터 연결 단계에서 실사진·계좌·공유 키를 한 번에 채운다.

## 3. 디자인 톤

- 픽셀 게스트북의 "모던 UI"와 같은 가족이어야 한다: 크림색 바탕(`#faf6ee`), 포인트 장미색(`#a95670`), 연한 장미 배경(`#f5e5e9`), 글씨 `Pretendard Variable`(CDN, 픽셀 앱과 같은 주소), 둥근 카드(반지름 18px), 얇은 선(`#dfdace`).
- 사진·달력·지도 버튼 등 구역 사이는 넉넉한 여백(48px 이상). 구역 제목은 작은 영문 라벨(10px 이상, 자간 넓게) + 한글 제목 20px.
- 픽셀 요소는 **표지 폴백과 8번 정원 안내 그림에만** 쓴다. 나머지는 일반 청첩장답게 사진과 글이 주인공이다.
- 애니메이션은 스크롤 시 구역이 살짝 떠오르는 페이드 하나만. `prefers-reduced-motion`이면 끈다.
- 다크 모드 대응은 하지 않는다(청첩장은 밝은 톤 고정). `color-scheme: light`.

## 4. 코덱스 작업 지시 (9차)

### 만들 파일
```
groom/index.html            신랑측 페이지. <html data-side="groom">
bride/index.html            신부측 페이지. <html data-side="bride">
classic/app.css             공용 스타일
classic/app.js              공용 스크립트(ES 모듈, 빌드 없음)
classic/img/garden-preview.png   픽셀 정원 미리보기 그림 (아래 규격)
classic/img/og-groom.png, og-bride.png   카카오톡·메신저 공유 미리보기 1200×630 (같은 디자인, 사진 자리는 크림색 + 두 사람 픽셀 그림)
```
- `groom/index.html`과 `bride/index.html`은 **`data-side`와 `<title>`·`og:` 메타만 다르고 나머지는 동일**해야 한다. 공통 마크업은 `app.js`가 설정을 읽어 채운다(두 HTML에 내용을 직접 적지 않는다).
- `app.js`는 `../data/config.json`을 fetch로 읽는다(실패 시 "준비 중" 한 줄과 함께 빈 페이지가 아닌 뼈대는 보이게). `gallery/manifest.json`도 `../gallery/manifest.json`.
- 설정에 **새 필드** `classic`을 추가한다(기존 필드는 건드리지 않는다):
  ```json
  "classic": {
    "invitation": "서로 다른 길을 걸어온 두 사람이\n이제 같은 길을 함께 걷고자 합니다.\n저희 두 사람의 새로운 시작을\n마음으로 함께해 주시면 감사하겠습니다.",
    "coverPhoto": ""
  }
  ```
  `coverPhoto`가 비어 있으면 갤러리 첫 사진, 그것도 없으면 폴백 그림.
- 계좌 구역: `data-side`가 `groom`이면 `config.groom`, `bride`면 `config.bride`만 렌더한다. 상대측 계좌는 DOM에 아예 넣지 않는다.
- 복사 버튼은 `navigator.clipboard.writeText` 실패 시 `document.execCommand('copy')` 폴백(카카오톡 인앱 브라우저 대응). 복사 후 2초 토스트.
- 전체 화면 사진 뷰어: 좌우 스와이프, 닫기 버튼, `contextmenu`·`dragstart` 차단, 이미지 `-webkit-touch-callout: none`, `user-select: none`(픽셀 앱 `js/ui/viewer.js`와 같은 수준의 저장 억제. 완전한 방지는 불가능하다는 점은 그대로).
- 지도 버튼: `wedding.map.kakao/naver/tmap` 중 값이 있는 것만 보인다. 외부 링크는 `target="_blank" rel="noopener"`.
- 카카오톡 공유: `kakaoJsKey`가 있을 때만 Kakao SDK(`https://t1.kakaocdn.net/kakao_js_sdk/2.7.4/kakao.min.js`, integrity 포함)를 동적으로 불러와 `Kakao.Share.sendDefault`(feed) 호출. 키가 없으면 버튼 숨김. 공유 제목 "진민우 ♥ 한새암 결혼합니다", 설명은 날짜·장소, 이미지는 `og-groom.png`/`og-bride.png`의 절대 URL(`siteUrl` + 경로; `siteUrl` 비어 있으면 `location.origin` 기준).
- 접근성: 구역마다 `<section aria-labelledby>`, 버튼은 `<button>`, 이미지 `alt`, 포커스 표시 유지. 키보드로 뷰어 닫기(Esc)·넘기기(←/→).
- 성능: 썸네일은 `loading="lazy"`, 외부 폰트 외에 다른 CDN 라이브러리 금지(카카오 SDK 제외).
- 호환: iOS 15 사파리·카카오톡 인앱·삼성 인터넷. 최상위 `await` 쓰지 말 것(모듈 안에서 async 함수로 감싼다).

### 그림 규격
- `garden-preview.png` 352×240: 현재 픽셀 정원 상단(아치·단상·두 사람·하객 몇 명)을 **새로 그린** 한 장. 기존 배경 조각 `assets/maps/hub-top.png`과 캐릭터 PNG를 합성해 만들어도 된다(복사·합성 허용). 32색 제한 없음, 투명 없음.
- `og-groom.png`, `og-bride.png` 1200×630: 크림 바탕, 가운데 두 사람 픽셀 그림(`assets/characters/couple.png` 확대, 픽셀 유지), 아래 "진민우 ♥ 한새암 / 2027. 01. 09 SAT 11:30 AM / 더그랜드롯데 서울 38층 무궁화". 두 장은 동일해도 된다(파일만 둘).

## 5. 사용자 확인이 필요한 점

1. **축의금 방침 충돌.** 픽셀 게스트북은 `gifts.declineMoney: true`로 축의금을 정중히 사양한다고 안내한다. 일반형 청첩장에는 계좌를 싣기로 했으므로 두 안내가 다르다. 이 설계는 "일반형 페이지에는 계좌를 싣고, 픽셀 정원의 사양 안내는 그대로 둔다"로 가정했다. 픽셀 정원도 계좌를 보여 주려면 `declineMoney`를 `false`로 바꾸면 된다(이미 "계좌 보기" 버튼이 있다).
2. **부모님 계좌.** 설정에 부모님 계좌 필드(`parents[].account`)가 아직 없다. 넣을지, 신랑·신부 본인 계좌만 둘지.
3. **전화번호 노출.** 혼주 구역에 전화 아이콘을 둘지(현재 번호는 자리표시자).
4. **루트 주소.** `/`를 `/common/`으로 보낼지, 아니면 세 링크를 고르는 작은 안내 페이지로 둘지. 이 설계는 즉시 이동으로 가정했다.
